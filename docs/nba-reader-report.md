# NBA 일일 보고서 개선

사용자가 먼저 볼 내용은 ① 짧은 요약 ② 직전 추천 복기 ③ 전 경기 분석이다. 기존 수치 전체는 ④ 상세표, 회고 모델 비교는 ⑤ 검증 현황, 수집 오류·ID·해시·코드 검사는 ⑥ 기술 진단에 둔다. 마지막 ⑦에 오늘의 최종 픽 3개와 각각의 이유·위험을 둔다. HTML의 ④~⑥은 접어서 제공한다. 문서와 텔레그램 캡션에 같은 TOP 목록을 사용한다. Markdown 원본을 유지하고 모바일 HTML을 함께 생성한다. 기존 저장 보고서를 재전송할 때는 과거 본문과 선택을 바꾸지 않는다.

## 변경 파일

- `sporton/nba_report.py`: 쉬운 한국어 문장과 마지막 최종 픽 렌더러, 작은 비교표, 한국시간, 누락 값 표현, HTML 및 텔레그램 요약.
- `sporton/daily_picks.py`: 경기 전 TOP 1~3 선정, 원본 저장, 전달 시각 검증, 유형별 채점 및 피드백. 한 경기에서 한 선택만 추천한다.
- `sporton/dispatch.py`: 기존 수집→감사→생성 흐름에 새 렌더러/추천 기록을 연결하고 원본별 문서·HTML을 저장한다. 기존 기술 렌더러도 보존했다.
- `sporton/nba_quality.py`: 원본 보고서별 전 경기 오차를 반환하고, 실제 사전 구간 예상이 있을 때만 전반/쿼터 오차를 계산한다.
- `sporton/telegram.py`: 새 형식은 핵심 요약 캡션과 HTML 첨부를 보낸다. 구형 Markdown 첨부와 전달 중복 방지는 유지한다.
- `tests/test_daily_reader.py`, `tests/test_telegram.py`: 추천 고정·유형 분리·조건 검증·시각 제외·호환성·HTML 전달 테스트.

## 추천과 복기가 이어지는 방식

1. 수집한 경기/가격/선수 자료와 기존 코드 검사 결과를 보존한다.
2. 실제 생성 시각 기준 시작 전이고, 최소 전력 표본과 기존 검사를 통과한 경기에서 TOP을 선정한다. 기존 공식 추천 자격을 새로 완화하지 않는다.
3. 공식 가격픽은 기존 공식 결정·예측·검사·검증 가격 원본이 일치할 때만 인정한다. 공개 조회 가격은 관찰 픽이다. 실제 가격을 조회하지 못한 조건부 픽의 문턱은 자체 기준이라고 명시하고 배당을 만들지 않는다.
4. `professional_reports.content.top_picks`와 `market_selections.kind=daily_top_pick`에 순위·팀·시장·기준점·배당·시각·예상 점수·근거·위험·원본 해시를 저장한다. 기존 보고서/브리핑/전 경기 예측과 같은 트랜잭션으로 고정한다.
5. 다음 감사에서 원본 해시와 경기 전 저장 시각, 경기 전 텔레그램 성공 영수증을 확인한다. 성공 기록이 없거나 시작 후 전달됐으면 사전 추천 성적에서 제외한다.
6. 결과는 `settlement_events.kind=daily_top_pick_audit`, 피드백은 `learning_feedback.kind=daily_top_pick_feedback`로 추가한다. 추천 원본을 갱신하지 않는다. 적중 픽도 점수 오차와 과정 차이를 검토한다.
7. 공식/관찰/조건부 누적 성적은 분리한다. 공식 픽의 가격이 있을 때만 동일 단위 참고 ROI를 계산하며 실제 투자 손익으로 표현하지 않는다. 전 경기 방향/점수 오차도 별도로 계산한다.

조건부 픽은 `record_condition_quote`로 경기 전 실제 가격 증거를 기록했을 때만 채점한다. 이 함수는 경기·선택·조건·출처·기록 시각을 검사한다. 현재 자동 가격 재조회/조건 활성화 작업은 추가하지 않았다. 따라서 해당 증거가 없으면 다음 날에도 “조건 충족 미확인 · 성적 제외”가 정상이다.

이전 `top_watch`는 당시 불변 보고서에 실제 선택·기준점이 있고 경기 전 전달 기록도 있는 경우에만 관찰 픽으로 복원한다. 복원 시각과 원래 추천 시각을 구분한다. 새 형식 보고서에 TOP이 없으면 구형 후보 목록을 추천으로 복원하지 않는다.

## 데이터 호환성

테이블 변경이나 데이터 삭제는 없다. 기존 append-only 테이블에 `kind`로 구분한 레코드를 추가한다. 기존 `games`, `audit`, `top_watch`, Markdown 및 원본 자료를 유지하고 `top_picks`, `report_format_version`을 추가한다. 구형 전 경기 감사 결과에는 연결된 원본에서 보고서 ID와 팀명을 읽어 표시하며 저장 원본을 바꾸지 않는다.

최근 5/10경기·시즌·홈/원정·표본·득실점, 파생 효율, 선수 상태, 일정 간격, 가격/조회 시각/공개 시각, 예상과 시장 차이, 연구 모델 MAE/Brier를 상세표에 유지한다. 파생 포제션과 공식 포제션은 구분한다. 원본 JSON은 DB에 그대로 남는다.

## 확인 범위와 한계

별도 생성형 AI/전문가 심사, 새 선수 역할 모델, 검증된 승률 모델을 추가한 작업은 아니다. 인과 자료가 부족한 복기는 사실·가설·미확인과 다음 점검 항목을 구분한다. 한 경기로 가중치를 변경하지 않는다. 시장과 예상 점수의 차이는 검증된 수익 우위가 아니다.

자동 보고서 진입점은 기존 `sporton.dispatch`를 유지한다. 형식 버전은 `reader-v2`다. 이미 전달한 과거 보고서는 그대로 보존하며, 새 보고서부터 마지막에 최종 픽을 둔다. 예약 작업은 GitHub Actions에서 실행하므로 이 채팅의 Cloud 환경과 독립적이다. 환경 게시 설정과 예약 시간은 변경하지 않는다.

- 실제 데이터 재렌더링: 4경기. 별도 복사 DB에서 기존 TOP 원본 7건 복원. 직전 보고서의 TOP 1건은 저장 결과가 없어 **결과 확인 중**으로 표시했다. 실결과를 새로 조회해 과거 성적을 완성한 검증은 아니다.

- `git diff --check`: 통과.

## 2026-11-15 추가 수정

본문은 결론→이유→위험 순서의 짧은 한국어 문단으로 바꿨다. 핸디캡은 어느 점수 차에서 적중하는지 설명하고, 총점은 예상 합계와 기준점을 비교한다. 내부 실행 ID와 해시도 최종 픽보다 앞에 넣어 실제 문서 끝에 추천만 남긴다. 세 경기를 추천할 자료가 있으면 서로 다른 세 경기에서 고른다. 자료나 시작 전 경기가 부족하면 없는 선택을 만들지 않고 가능한 개수를 밝힌다.

최종 3개와 저장·다음 감사의 일치, 전일 3개 개별 채점, 요약의 세 선택 보존, 내부 ID의 위치, HTML 상세 접기 동작을 테스트한다.

환경 중단 당시 제공된 오류는 “managed environment was suspended before becoming ready”였다. 현재 같은 환경은 `running`/`connected`, 관측도 최신이다. 진단 조회는 `history_status=not_found`로 과거 기록을 제공하지 않았다. 따라서 준비 전 일시 중지됐다는 사실은 확인되지만, 플랫폼이 중지한 근본 원인·주체·정책을 단정할 근거는 없다.
