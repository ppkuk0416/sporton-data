## 다음 작업

1. 사용 권한이 확인된 NBA·축구·야구 공급자와 시점 증거 확보. 축구/야구는 현재 정규화 CSV 입력 경로이며 자동 공급자 어댑터는 미연결. 네트워크 설정에서 stats.nba.com 허용 검토 후 공식 API 재시도. 세 시즌 결과/정확한 tipoff/period 점수/공개 시각 CSV 검증. API raw만으로 시점을 만들어내지 않는다.
2. 실제 세 시즌에서 시즌 단위 고정 검증, 시장 baseline 및 calibration/표본 부족 진단. 최초 Champion을 연구용으로 등록하고 실제 사전 예측 감사 축적.
3. possession 기반 ORtg/DRtg, 부상·라인업·휴식·travel·로스터 변경 등 실제로 확보한 피처 추가. 독립 반대 근거 심사 강화. 공급자별 정정 승인 절차 고도화. 결과 정정의 불변 이력·as-of 해석은 구현했다.
4. spread/total용 공동 득점 분포 및 쿼터별 모델, 실제 시장 feed와 price timestamp 검증.
5. 기본 모델과 비교 가능한 충분한 실제 데이터가 생긴 후 PyTorch 비교. 개선이 없으면 채택하지 않음.
6. KBL은 NBA와 별도 리그 모델, 해당 시즌 외국인 선수 규정을 공식 출처로 확인한 후 연결.

이 상태를 PHASE 1 전체 완료나 고정확도 실전 서비스로 표현하지 않는다. 실행 가능한 연구 MVP와 검증 인프라가 구현된 상태다. 컨테이너 설정은 제공하지만 현재 Python 서비스 및 실제 PostgreSQL Docker의 저장·권한·백업/복원은 검증했다. 전체 앱 이미지 빌드·운영 Compose 배포와 외부 DB/백업은 미검증이다.

축구·야구 모델은 TEST/FIXTURE로 실행 검증하는 연구 구현이며, 실제 세 시즌 학습이나 실전 정확도 확보를 의미하지 않는다. 생성형 분석 LLM도 아직 연결되지 않았다.

## 정기 브리핑 추가

한국시간 매일 06:30/17:00 대시보드 브리핑과 원본 보관을 구현했다. 지난 경기와 사전 예측, 앞으로 24시간의 등록 일정, 이전 브리핑 이후 변화, 논의 주제, 데이터·모델·오류 상태를 묶는다. 매시간 데이터 입력·결과 감사·조건부 후보 학습과 정기 브리핑 후 로컬 SQLite/모델 백업을 지원한다. 상시 호스트, 실제 일정/결과/시장 공급자, 원격 백업은 여전히 별도 과제다. 이 채팅의 정기 메시지 예약 기능은 연결되지 않았으며 사용자가 선택한 전달 경로는 앱 대시보드다.

## 직접 수집·PyTorch 추가

라이선스가 확인된 NBA 역사 59,008경기와 EPL 3시즌 1,140경기 원본을 직접 확보했다. 원본/라이선스/SHA256을 보존하는 수집기와 주기적 수집을 연결했다. PyTorch MLP 학습·교정·기준 모델 비교 및 NBA/종목별 운영 후보 경로도 구현했다. EPL 아카이브의 최종 테스트에서 딥러닝 개선이 확인되지 않아 운영 승격하지 않았다. 정확한 공개 시각이 없는 아카이브는 date_only_archive로 분리한다. KBL 공식 접근, 실시간 정상화 feed, 엄밀한 검증 데이터 확보는 여전히 외부 접속 설정 적용과 후속 구현이 필요하다. 상세 결과는 collection-and-deep-learning.md에 기록했다.

## 영구 보존 기반 v0.3 추가

PostgreSQL 53개 테이블, 앱/owner 역할 분리, 원본 UPDATE/DELETE/TRUNCATE 차단, DB 서버 사전 게시 게이트, 증거를 갖는 불변 정정, 출처·결측·충돌 관측, 종목별 독립 통계 열, Parquet/DuckDB, 암호화 백업·실제 격리 복원·복원 실패 경고·재시도·보존기간, 관리자 인증/원본 추적을 구현했다. 기존 SQLite 원본을 보존하며 이관했고 실제 60,148 아카이브 행을 분석 파일로 검증했다.

남은 운영 과제: 외부 PostgreSQL과 다른 호스트 백업 저장소/키 관리, PostgreSQL 물리 base backup과 실제 PITR 복구 훈련, 상시 호스트·프로세스 감독, 운영 인증 서비스, 최신 일정/선수/시장 공급자, 각 종목의 실제 전문 피처·독립 생성형 심사 및 실전 모델 검증. 현재 같은 호스트의 개발 자료를 외부 장애까지 보장된 영구 저장이라고 부르지 않는다. [실제 검증](validation.md)과 [보존 범위](persistence.md)를 함께 본다.
