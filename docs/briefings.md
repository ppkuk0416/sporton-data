# 데일리 브리핑 · 06:30 / 17:00 Asia/Seoul

사용자가 선택한 전달 방법은 **앱 대시보드**다. 두 시각 모두 한국시간이며 각각 UTC 전날 21:30 / 당일 08:00이다. 브리핑은 모든 구현 종목을 함께 요약한다. 일반 채팅 알림·메일·메신저 전송은 연결하지 않는다.

## 내용

1. 지난 브리핑 이후 새로 공개된 경기 결과, 새 감사 결과, 아직 결과를 확인하지 못한 경기. 저장된 사전 예측의 ID·모델·점수와 실제 결과·마진/총점 오차·Brier를 비교한다. 예측이 없었던 경기를 사후 적중으로 만들지 않는다.
2. 앞으로 24시간의 **등록된 일정**, 다음 브리핑 전에 시작하는 경기, 종목별 분석기·모델·예측 범위·교정된 연구 확률·불확실성·독립 심사·시장 선택. 리그별 Champion이 없거나 데이터가 부족하면 분석 불가로 표시한다.
3. 이전 브리핑에서 안내한 경기의 결과 확인, 새 일정과 새 감사, 모델 교체 이벤트. 원본 예측 이후 추가된 부상·선발/타선 context·시장 정보는 재심사 필요로 표시하고 원본 추천을 현재 유효한 것으로 재확인하지 않는다.
4. 종목별 누적 자료, 신규 입력/공개 결과, 실전 감사 표본, 실제 성능 또는 미측정, 최신 학습/검증, Champion과 drift, 수집 실패·작업 문제.
5. 앞서 합의한 운영 원칙과 추적 주제, 미구현 종목·공급자·LLM 연결 상태. 원본 UTC 저장, 화면 한국시간 표시, 실제 자료만 사용, 누출 방지, 심사·예측 불변 보관, 검증된 후보만 승격 원칙을 정책 버전으로 저장한다.

모든 일반 채팅 내용을 자동으로 읽거나 영구 수집하는 기능은 없다. 정책·등록 주제·이전 브리핑·예측·심사·경기 결과를 DB에서 추적한다. 더 기억할 주제는 아래 명령으로 명시적으로 등록한다.

```bash
sporton briefing-note '매 브리핑에서 추적할 주제'
```

## 실행

```bash
cd /workspace/sporton-data
# 지금 실제 시점 기준 수동 브리핑
/workspace/.venvs/sporton/bin/sporton briefing
# 정시 생성 + 매시간 inbox 입력/결과 감사 + 조건부 후보 재학습
/workspace/.venvs/sporton/bin/sporton briefing-daemon --inbox var/inbox --retrain
# 단발 예약 점검
/workspace/.venvs/sporton/bin/sporton briefing-daemon --once
```

daemon은 매 30초 이내 예정 시각을 확인하고 06:30·17:00에 슬롯당 한 번 저장한다. 별도로 시간당 한 번 CSV inbox 입력과 결과 감사를 점검한다. `--retrain`이면 최소 100 usable input games를 갖춘 리그에 기존의 신규 결과 50경기·시간순 분할·교정·새 홀드아웃·승격 gate를 적용한다. 조건 미달·오류는 기록하고 기존 모델을 무조건 교체하지 않는다. 브리핑 생성 직전에도 inbox와 결과를 갱신하고 앞으로 24시간 경기 중 아직 게시되지 않은 경기를 현재 Champion으로 분석·독립 심사한다. 시장 가격을 자동으로 만들어 채우지 않는다.

**브리핑 daemon이 데이터 입력/감사를 담당하므로 같은 DB에 기존 worker나 다른 학습 writer를 동시에 실행하지 않는다.** 여러 종목은 같은 daemon에서 순차 관리한다. scheduler lock으로 브리핑 daemon 중복 실행을 막는다.

서버/daemon이 중지되면 정시 실행도 중지된다. 다시 시작할 때 가장 최근 예정 슬롯 하나만 현재 시점 기준으로 생성하고 지연을 표시한다. 이전 실행 후 여러 슬롯을 놓쳤다면 누락 슬롯을 이벤트로 기록하며 과거 사전 브리핑을 만들어내지 않는다. 수집·예측 처리 시간이 길어져도 실제 생성 시각과 지연을 숨기지 않는다. 정시 생성에 대한 실시간 SLA는 없다.

## 대시보드와 보관

대시보드 상단의 **데일리 브리핑**에서 예약 프로세스 관측 상태, 다음 예정 시각, 보관된 원본 선택, 전문과 원본 링크를 확인한다.

- `GET /api/briefing-status`: 고정 시간대·시각, lock과 heartbeat를 통한 현재 실행 관측, 다음 예정.
- `GET /api/briefings`: 실제 모드 브리핑 목록. TEST/FIXTURE는 제외.
- `GET /api/briefings/{id}`: 시점이 고정된 전체 스냅샷·참조 ID·원문.
- `GET /api/briefings/{id}/markdown`: 평문 원본.

DB `briefings`, `briefing_notes`, `briefing_events`는 기존 append-only·SHA256 검증을 적용한다. Markdown 사본은 `var/briefings/{id}.md`에 저장한다. 같은 슬롯 재호출은 원본을 돌려주며 DB 기록이 남아 있으면 누락된 Markdown 사본을 복원한다. 이미 존재하는 사본이 원본과 다르면 오류로 알린다. 정기 브리핑 생성 후에는 `var/backups/{briefing-id}`에 SQLite 일관성 백업과 모델 파일·해시 manifest를 보관하고 성공/실패를 이벤트로 기록한다. 원격 백업은 연결하지 않았다. 백업에는 DB 전체에 브리핑·주제·이벤트가 포함되고 Markdown은 DB 원문에서 재생성할 수 있다.

## 상시 운영과 현재 한계

Docker 설정은 `docker compose --profile briefing up --build dashboard briefing`로 제공한다. `restart: unless-stopped`이지만 **상시 켜진 호스트**가 필요하고, 현재 클라우드 세션의 종료 이후 실행을 보장하지 않는다. 컨테이너 빌드는 아직 검증하지 않았다. 환경 start_skill에 API와 briefing daemon을 다시 시작하는 절차를 등록한다. 설정 초안 저장·환경 게시·새 태스크 복원은 서로 별개다.

실제 일정/결과/시장 공급자가 연결되지 않았고 실제 경기 자료도 아직 없다. 정규화 CSV inbox와 별도로 공개 라이선스를 확인한 NBA/EPL 아카이브를 직접 주기 수집한다. 아카이브와 연구 결과는 verified 경기·실전 성능과 분리해 브리핑에 표시한다. KBL 공식 페이지는 아직 접근 차단 상태이며 일정/결과 추출기는 검증되지 않았다. 일정이 비어 있다고 실제 경기가 없다는 뜻이 아니다. 다음 시각의 브리핑 본문은 그 시점의 DB와 수집 상태에 따라 생성되며 지금 미리 만든 스포츠 예측을 예약해 게시하지 않는다.
